# 初版核对与速度比较

2026-10-23，本机 NVIDIA GeForce RTX 5070 Ti，16 GB 显存，WebGPU / NVIDIA Blackwell。下面是原始 JSON 的摘要，不是对实机飞行性能的验证。

## 当前默认 FP32 工况

记录：[standard-fp32.json](validation/standard-fp32.json)。采用已拼接翼根的 NASA WING01 全翼、两片研究翼刀和四片研究扰流板，迎角 8°，`Re_MAC=2,000`，`Cs=0.14`。

| 项目 | 当前记录 |
|---|---:|
| 网格 | 240 × 224 × 96，5,160,960 单元 |
| 推进步数 | 23,448 |
| 对流时间 `t U∞ / MAC` | 79.78 |
| 全场有限值 | 是 |
| 密度范围 | 0.99312–1.01000 |
| 平均密度 | 0.999952 |
| 最高局部马赫数 | 0.156 |
| 瞬时 `CL` | 0.290 |
| 瞬时 `CD` | 0.210 |

四个近壁探针的上表面 `Cp` 约 −0.29 至 −0.36，下表面约 +0.10 至 +0.18。下游 `x/c_root=2.3` 两侧观察窗中的环量分别约 `+0.0373`、`−0.0189`（以 `U∞ c_root` 归一化），流向涡量峰值分别约 `+3.92`、`−5.02`。这些量从流场和壁面动量交换直接计算，并未作为求解器输入。

尾迹随时间变化；观察窗可能同时包含主涡与次生涡，所列环量不能直接当作单一涡核强度。气动力是瞬时值，没有做统计平均。当前证据支持“机翼引起压力差、升力和反向旋转的三维近尾迹”，不支持定量实机性能结论。

## 必要的数值检查

1. 无机翼、均匀来流的同类风洞边界，推进 104 步后最大展向速度约 `8.5×10⁻⁶ U∞`，最大密度偏差约 `3.8×10⁻⁶`。求解器没有自行注入明显的翼尖型旋转。
2. 周期三维网格 `32×24×24` 上的剪切波，关闭亚网格黏性、取格子黏性 0.05，推进 256 步。与 `A(t)=A₀ exp(−νk²t)` 比较，速度扰动相对 L2 误差约 **0.76%**。这是低分辨率剪切波的黏性衰减核对，不是机翼验证。
3. FP32 基准与三维分块实现在同一几何、同一初值下推进 1,024 步，速度 / 密度场最大逐点差为 **0**。该分块改动没有稳定的速度收益，因此默认求解使用基准内核。

## 采用的显示批处理

比较时均为 FP32、相同几何、相同总推进步数，视口为 `1143×1125` 像素。每轮推进 144 步；包括场提取、涡量、流线和体渲染。以下是整段墙钟耗时，不是单独内核计时。

| 轮次 | 每 12 步更新显示 | 每 36 步更新显示 |
|---|---:|---:|
| 1 | 330.5 ms | 215.0 ms |
| 2 | 246.1 ms | 217.8 ms |
| 3 | 243.9 ms | 220.3 ms |
| 中位数 | 246.1 ms | 217.8 ms |

该比较中耗时降低约 **11.5%**，吞吐约为 **1.13 倍**。每侧累计推进 432 步后最大逐点场值差仍为 **0**。这验证了减少显示更新能节省开销，没有改变流体推进本身。

实际默认标准网格采用每次 24 步的折中批次，精细网格每次 8 步，以保留相机响应；它们不是上表 36 步方案的同一个计时设置。运行期间界面的 MLUPS 包括求解与显示成本，不能与单独内核吞吐混用。

## 未采用的混合精度加速

记录：[mixed-precision-rejected.json](validation/mixed-precision-rejected.json)。采用缩放的偏移分布函数、FP16 存储 / FP32 运算：

- 双缓冲分布函数由 152 降至 80 byte/cell；三次计时中位数由 129.4 降至 70.2 ms，约 **1.84 倍**。
- 但推进 1,024 步后的速度分量均方根差为 **0.0655 U∞**，`CL` 从约 0.489 变为 0.414，压力系数也发生明显偏移。
- 因此该方案仅作为明确标记的实验选项保留，**默认保持 FP32**。不能只引用加速比而忽略数值差异。

## 2026-10-24：FP32 融合提取与提交调度

记录：[标准网格](validation/scheduling-standard.json)、[精细网格](validation/scheduling-fine.json)。同一显卡、同一构型、迎角、FP32、默认全景、视口 `1143×1125`、Q 阈值 1.2，开启流线和翼尖聚焦。每轮均显示 8 帧，标准档每帧 24 步，精细档每帧 8 步。三轮交替先后顺序，比较原来的串行等待 / 三次提交，与当前融合场提取 / 一次提交 / 最多两帧在途的实现。

| 网格 | 原实现三轮耗时 ms | 优化后三轮耗时 ms | 中位数变化 | 端到端吞吐提升 |
|---|---|---|---|---:|
| 240×224×96 | 278.1 / 273.3 / 287.0 | 250.0 / 254.0 / 253.9 | 278.1 → 253.9 ms | **9.5%** |
| 360×336×144 | 329.1 / 323.6 / 323.3 | 291.3 / 284.5 / 288.4 | 323.6 → 288.4 ms | **12.2%** |

对应标准档约 3,563 → 3,903 MLUPS，精细档约 3,445 → 3,865 MLUPS，均包含浏览器刷新调度、求解和显示；相应墙钟耗时降低 8.7% 和 10.9%。这些是短段、同机成对测量，不表示所有硬件或长时运行都有固定加速比。没有提高每帧步数，也没有降低网格、显示采样或存储精度。

两侧均从相同均匀来流推进到 1,024 步。优化侧最后一步直接输出融合后的速度与密度，没有再用原提取过程覆盖它们。两档全场均为有限值，最大逐点场值差及速度分量 RMS 差均为 **0**，链路动量交换得到的 `CL/CD` 也完全一致。标准档 `CL/CD≈0.49358/0.30883`，精细档约 `0.54602/0.21160`；这是各自短时初始过程的瞬时值，不能据此判断网格收敛。

精细档随后继续运行，界面显示 `tU∞/MAC=35.51`、约 28 FPS、3,900 MLUPS，再暂停保留流场。调整缩放后的实际 CFD 画面保存为 [performance-preview.png](assets/performance-preview.png)。这段是交互与运行观察，不追加长时全场数值扫描或收敛结论。

新增 GPU 时间戳测量用于定位瓶颈，支持情况按浏览器特性检查；相关 API 见 [MDN beginComputePass](https://developer.mozilla.org/en-US/docs/Web/API/GPUCommandEncoder/beginComputePass)。基准独立阶段的代表性 24 步记录：标准档推进约 30.0 ms、提取 0.79 ms、涡量 0.20 ms、流线及渲染 0.52 ms；精细档推进约 99.7 ms、提取 2.82 ms、涡量 0.59 ms、流线及渲染 0.66 ms。短阶段受时间戳粒度影响，只用于区分主要开销。JSON 的 `core` 与 `rendered` 是同一基准求解器的分阶段重复测量；`scheduling` 才是最终实现的端到端比较。

本轮未采用的两条路线也保留测量证据：

- [Rust 生成的展开内核](validation/unrolled-fp32.json)：标准档 96 步 GPU 中位数 118.10 → 118.62 ms，无稳定提速，1,024 步全场差为 0。
- [十个 FP32 系数的矩基存储，标准档](validation/moments-standard.json)及[精细档](validation/moments-fine.json)：分布状态双缓冲从 152 降至 80 byte/cell，但 96 步 GPU 中位数分别为 119.01 → 124.32 ms、394.85 → 454.56 ms，反而更慢。1,024 步后速度分量 RMS 差约 `4.9×10⁻⁶ U∞`、`5.6×10⁻⁶ U∞`。已撤回这两条试验实现，避免把更少显存或使用 Rust 等同于更快。

## 范围与未解决问题

- `validation/initial-40-devices.json` 是早期 `Re=20,000` 的记录；虽为有限值，画面存在明显网格纹理，未将它接受为可信湍流结果。
- `validation/f32-40-devices.json` 和 `validation/tiling-only.json` 保留首轮 FP32 与微优化比较；其翼根仍为早期组装版本，应使用 `standard-fp32.json` 描述当前几何。
- 优化前已实际运行 360×336×144、17,418,240 单元的精细网格，界面观察约 22 FPS、3,120 MLUPS（含显示），随后在 `tU∞/MAC=33.52` 暂停。见 [fine-grid-observation.json](validation/fine-grid-observation.json)。该旧记录只检查实际启动、时间推进、缩放和画面；本轮新增的 1,024 步全场核对见上，仍未完成网格收敛研究。
- 精细档虽然总单元数较大，平均气动弦只有约 31 个网格，翼尖弦长约 12 个网格。细薄翼尖、涡核和装置仍欠分辨，下一步应优先做局部网格加密，而不是仅增加空旷远场的单元数。
- 体素 / 链路中点边界、薄翼尖与小装置分辨率、有限域出口和未解析近壁层仍限制定量精度。没有与同几何、同雷诺数的实验作直接数值对照。
