# 三摆滑轨控制实验

三根均匀钢杆通过三个平行铰轴连接，底部安装在水平滑轨上。运动由自编双精度非线性动力学计算；控制器通过有限精度编码器测量和滑块加速度指令控制机构。杆 1、2、3 的“上 / 下”指相对于地面的绝对方向。不同层的杆件投影可以重合，不计算杆件间碰撞。

## 当前状态与原计划核对

| 原计划 | 当前状态 |
|---|---|
| 独立物理与控制 Worker，控制器只读编码器 | 已实现；共享参数和纯方程，不共享真实状态、外力或反力 |
| 1 ms 双精度高频物理 | 已实现；高角速度时在每个外层步内细分，避免单次转角过大 |
| 有限精度、采样率、延迟及速度估计 | 已实现；改变传感配置不会将已有速度估计清零 |
| 八种平衡点附近的反馈 | 已实现并做过默认扰动下的局部检查 |
| 重点姿态之间连续、受约束地切换 | 按最新范围聚焦“下下下 ↔ 下上下”，已验证双向切换；其他目标保留为探索，不要求任意姿态互达 |
| 不规则扰动、受力、能量、滚动曲线与缩放平移 | 已实现 |
| 高帧率 | 已移除 60 FPS 上限；记录工况中实测绘制与运动更新 245–261 FPS，物理约 1000 步/s |

此前理想加速度模型的切换记录放在 `validation/previous-model/`，它们不能验证目前的电机模型。

## 运行

需要 Python、NumPy、SciPy、Numba，以及支持 Worker 和 JSON 模块的现代浏览器。Node.js 只用于数值核对。仓库根目录：

```powershell
python -m pip install -r triple-pendulum/requirements.txt
python triple-pendulum/server.py
```

打开 <http://127.0.0.1:8771/>。从默认“下下下”选择“下上下”可观察目前验证过的摆起。启动先积累约 0.5 s 的传感数据，规划在后台进行。目标切换、失败和恢复都保持物理状态连续；“重新开始”按钮才会显式重置状态。

拖拽平移、滚轮缩放、双击或“全域”恢复视角。传感器和扰动可在侧栏调整。结束时关闭页面，在服务终端按 `Ctrl+C`；页面关闭会终止两个 Worker。服务只监听本机。

## 本次诊断与修正

旧参考轨迹没有约束杆件转速，杆 3 峰值约 39.9 rad/s；旧动画每 80 ms 才收到一份状态，约 12.5 Hz 的运动信息会造成跳帧和旋转混叠。旧图表还会把 ±180° 的角度换支连成竖线。基线记录见 `validation/baseline-audit.json`。普通运动的步长对照没有显示积分自行发散，不能把目视高速旋转全部归因于数值不稳定。

当前增加了角速度和相对角速度约束、较大的黏性阻尼、执行器响应，并以独立物理模块重放检查闭环表现。旧激进轨迹仅保留为搜索初值，不能直接执行。没有找到新路线时显示失败，避免继续执行旧动作。跟踪偏离后采用反馈耗能恢复，而非只把滑块停住后任由杆件高速运动。

运动状态以 250 Hz 发布，完整受力和诊断维持 100 Hz；画面每次浏览器刷新都绘制，使用未换支角度和速度做 Hermite 插值。显示时钟单调推进，避免收到新快照时产生时间回跳；碰撞区间采用线性插值避免过冲。目标缓存约 12 ms，面板同时报告相对最新快照的实际插值滞后。插值只影响显示，不改变积分状态或控制输入。

背景网格交给浏览器缓存，Canvas 尺寸和坐标变换只在尺寸或像素比例改变时更新。曲线和数值面板保持 10 Hz，暂停时停止物理推进及持续场景重绘。FPS 同时记录真实绘制次数和仿真时刻推进的绘制次数，并显示帧间隔、绘制耗时的 P95，避免只看刷新回调数。

`validation/display-performance.json` 记录四个前台工况：普通视角、摆起、放大后耗能返回、暂停后恢复。窗口尺寸分别为 1280×720 和 944×903，像素比例 1.25，未降低绘制分辨率。记录窗口的绘制和运动更新为 245–261 FPS，帧间隔 P95 约 4 ms，绘制 P95 约 0.1–0.2 ms；这不等同于测量显示器实际扫描输出。浏览器刷新调度和显示设备仍会限制上限，见 [requestAnimationFrame 官方文档](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)。

## 物理与执行器

| 杆 | 长度 / m | 质量 / kg | 直径 / mm |
|---|---:|---:|---:|
| 1 | 0.323 | 0.876 | 20.974 |
| 2 | 0.419 | 0.938 | 19.055 |
| 3 | 0.484 | 0.553 | 13.613 |

钢密度 7850 kg/m³，质心在中点，圆柱横向质心惯量采用 `m(L²+3r²)/12`。滑块质量 2 kg，轨道 ±0.7 m，速度上限 3 m/s，指令加速度上限 22 m/s²。参数集中在 `parameters.json`；修改后需重启服务及重载页面，已有参考路线需要重新验证。

三个铰链的相对角速度黏性阻尼分别为 0.012 / 0.009 / 0.006 N·m·s/rad，耗散功率为各铰链 `d·ω_relative²` 之和。电机采用 **5 ms 固定指令延迟和 20 ms 一阶响应**，实际加速度作为第九个状态积分。这些是演示假设，未做硬件标定；不包含电流环、齿隙、静摩擦、静态磁滞或转矩饱和。驱动力由运动反算，仍是加速度伺服近似。

物理外层固定 1 ms RK4；内部步长还限制单步角位移约 0.006 rad。到达轨道或速度边界时定位事件，端点碰撞将滑块速度置零，并通过质量耦合冲量改变角速度。没有对杆角、角速度做视觉限幅，没有用预设运动覆盖物理状态。

每根杆质心受到独立有界随机水平力，默认上限 0.02 N、种子 7201；各类力箭头分别缩放，不能跨类别按箭头长度比较大小。

## 传感、反馈与规划

默认测量为 100 Hz、12 位铰链相对角编码器、0.1 mm 位置分辨率、10 ms 延迟及小幅可复现噪声。控制器只接收位置、角度和时间信息，速度与电机状态由自身模型估计。理想测量关闭量化、噪声和传感延迟，但保留电机响应。

物理 Worker 在采样交付点等待对应控制回复，随后继续按仿真时间积分。浏览器消息变慢会表现为仿真相对墙钟滞后，不会偷偷改变物理控制延迟。后台优化不参与此等待。测试额外注入 20 ms 墙钟消息延迟后，同一 2 s 仿真状态与正常运行完全一致，墙钟耗时增大，见 `validation/timing.json`。

八个平衡点分别设计包含电机状态和前一指令的离散 LQR。观测器按指令历史对齐延迟测量，使用解析动力学雅可比传播协方差，替代逐列扰动 RK4；协方差较长时间间隔也会细分传播。

后台 SciPy 搜索有界加速度轨迹，检查轨道、速度、转速及执行器响应。新增的离线多段射击工具用于重建参考。当前 `data/references.json` 只包含经过闭环重放的“下下下 → 下上下”，适用于 100 Hz 控制和目标附近的起始状态；其他采样率和远离参考起点的情况会重新搜索，可能失败。`data/initial-guesses.json` 中的旧轨迹只用于初始化优化。

多段射击的局部残差很小，并不保证敏感系统长时间开环重放后仍到达同一终点。因此当前参考还经过真实物理模块、有限传感器及扰动下的闭环检查；**动画只运行独立物理模块**。当前参考每 10 ms 的局部动力学残差最大约 6.6×10⁻⁶（各状态分量按 SI 单位），这不等同于物理积分误差。

直接切换失败后，可在已有验证边中搜索最多两个中间平衡点。当前支持先耗能到“下下下”，再进入“下上下”。“上下上”已捕获后若失稳，也会尝试先恢复后转向“下上下”；搜索失败不被解释成平衡点本身不可稳定。

## 验证结果与限制

- `validation/physics.json`：2.4 s 分段外力和指令，对照独立 SciPy DOP853，1 ms 最大状态分量差约 1.1×10⁻⁸，半步约 7.0×10⁻¹⁰；另检查了高能高速初态、碰撞和电机阶跃。高速初态 2 s 对照的最大分量差约 2.3×10⁻⁵，需与普通情况分开看。解析雅可比与中心差分最大差约 4.0×10⁻⁹。
- `validation/closed-loop.json`：八种平衡点附近各 20 s，默认扰动和传感器下均未失稳、未撞轨，最大角偏差约 5.27°。0.1 N 强扰动和较差传感器仍出现失稳，不能保证任意扰动下稳定。
- `validation/transition-0-2.json`：理想测量无外力，以及两个默认扰动种子，共三次 20 s 检查均完成“下上下”捕获且无碰撞。杆 3 峰值约 13.2 rad/s；两个扰动例的末端角误差均小于约 0.4°，瞬时跟踪误差和轨道余量仍需关注。
- `validation/routes.json`：列出全部 56 个有向组合。本次 14 组已有路线做过闭环检查并完成，另外 42 组未完成当前模型下的完整路线验证。这个有限集合不能推出任意姿态都能互相到达。
- 页面实查完成重点双向切换、放大和平移，记录的摆起与耗能返回工况均无碰撞，绘制和运动更新均超过 150 FPS。`validation/display-physics-regression.json` 显示提高发布和绘制频率前后，同一仿真时刻的物理状态差为零。`validation/presentation.json` 另核对了有投递抖动时显示时钟不会回退。性能依机器、浏览器调度和场景而变，当前保持 JavaScript f64。

在本目录需要复核时，运行 `python verify.py`；启动服务后可运行 `node verify_closedloop.mjs`、`node verify_transition.mjs 2`、`node verify_routes.mjs`、`node verify_timing.mjs`，显示时钟检查使用 `node verify_presentation.mjs`。按改动选择必要检查，正常启动不会自动运行它们。本轮没有重新搜索全部姿态切换。

重新生成候选可运行 `python optimize_reference.py 2 5 60 23`、`python build_candidate.py 2`，再用 `node verify_transition.mjs 2 --candidate` 独立重放。候选不会自动写入生产参考；搜索受预算和初值影响。旧模型的 56 组直接规划记录保留为历史，不用于本版验收。

## 参考

[Glück、Eder、Kugi，Automatica 2013](https://www.acin.tuwien.ac.at/fileadmin/cds/pre_post_print/glueck2013.pdf) 给出了三摆、相对铰链阻尼、有限轨道和反馈跟踪的实验背景。其理想下级伺服假设和 1 ms 控制采样不同于本演示的有限传感及电机滞后，不能直接借用其成功结果。[MIT Underactuated Robotics 的 LQR 章节](https://underactuated.mit.edu/lqr.html) 说明局部线性控制及轨迹反馈背景；有界最小二乘使用 [SciPy 官方接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)。
